# Matched sets — created 2026-08-09

AOV is the binding constraint on this store. At ~$54 AOV and ~65% margin the
contribution per order is roughly $35, which is below realistic cold US apparel
CAC ($35–70). That makes paid acquisition break-even at best, and it is the
reason the unit economics do not currently support scaling. Sets are the lever
that moves AOV without touching margin.

## What was created

| Handle | Price | Was | Cost | Margin | Sizes | Stock |
|---|---|---|---|---|---|---|
| `womens-training-set-bra-ankle-leggings` | $79 | $92 | $21.95 | 72.2% | S–XL | 2,000 |
| `womens-yoga-set-halter-bra-yoga-pants` | $89 | $103 | $32.96 | 63.0% | S–XL | 2,000 |
| `mens-training-set-tee-shorts` | $65 | $76 | $21.95 | 66.2% | S–2XL | 2,500 |

All three clear the 60% margin floor set in `pricing.py`. Existing
`voltcore-2-piece-set-...` ($79) was already live and is unchanged.

Components (unchanged, still sold individually):

- Training set — Women's Cropped Sports Bra ($38) + Women's High Rise Ankle
  Length Leggings ($54). Both 230 g/m², both 89% polyester / 11% spandex.
- Yoga set — Women's Halter Neck Yoga Sports Bra ($49) + Women's High Rise
  Yoga Pants ($54). Both 220 g/m².
- Men's set — Men's Regular Fit Performance T-Shirt ($34, 130 g/m²) +
  Men's Drawstring Training Shorts ($42, 165 g/m²).

Pairs were chosen so both halves share a fabric weight wherever possible. That
keeps a single `spec.gsm` truthful for the whole set. The men's set has two
different weights, so it carries NO `spec.gsm` metafield and states both
figures in `spec.composition` instead — the product template only renders spec
rows that hold a value, so the Fabric weight row is simply absent rather than
showing a number that is wrong for one of the two pieces.

## Discovery

New smart collection `sets` (rule: product_type = Set) picks up all four
automatically, including any set added later. Added as the FIRST item in
`main-menu`, and published to all six sales channels along with the products.

## A mistake worth recording

`productSet` with `files.originalSource` pointing at an existing Shopify CDN
URL does NOT create new media. Shopify deduplicates by source URL and REUSES
the existing `MediaImage` record — so the `alt` supplied for the set silently
overwrote the alt text on all six component products. Same failure mode as the
flare-leggings/Voltcore incident earlier in this project.

Caught by comparing media IDs on the new sets against the components, and
fixed with `fileUpdate` across 12 images, restoring the garment-accurate text.

Because one `MediaImage` carries one alt, a shared image cannot hold different
alt text per product. The garment-accurate wording is the correct choice: it is
true on the standalone page and still true on the set page.

**Rule for next time:** to give a bundle its own alt text, the image must be
uploaded as a genuinely new file (different filename, or `duplicateResolutionMode:
APPEND_UUID`), not referenced by an existing CDN URL.
